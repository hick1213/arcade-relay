# design-docs — 编辑 design/ 时的强制规范

design/ 中的文档会被下游（实现、资产生成、QA）机械地引用。ID 与支柱的纪律以 contract.md §8 为权威来源。

## Do / Don't

- **Do**: 所有系统、所有资产条目都明确引用 `design/concept.md` 的支柱 `P-xx`（`pillar: P-01` / 「(P-02)」等）。gdd.md 的系统、assets.md 的各资产均为必需
- **Don't**: 不要添加对任何支柱都无贡献（＝写不出引用）的系统/资产。写不出来就删掉，或重新审视支柱
- **Do**: 游戏参数以**初始值＋调整范围**书写（例: `跳跃力: 420 px/s（调整范围 360–500）`）。实现侧把初始值抄写到 config.ts
- **Don't**: 不要写「以后再定」「适当调整」「偏快」等未确定值、仅有形容词的数值指定
- **Do**: 稳定 ID（支柱 `P-xx`、story `S-xx`）一旦分配即不可变。废止不是删除，而是以 status/注记（`（废止: 理由）`）表示
- **Don't**: 不要重新分配 ID、填补空号、复用 ID（下游的引用会全部损坏）
- **Do**: 各文档遵循 `.codex/docs/templates/` 中对应模板的标题结构。不得随意删除、改名模板的章节（新增章节放在模板章节之后）
- **Do**: 支柱 3～5 个，彼此独立，具有可用于裁定决策的具体性（DR-CONCEPT Gate 标准）

## 正误示例

### 支柱引用

```markdown
<!-- NG: 不清楚对哪个支柱起效 -->
## 系统: 连击
连续命中时倍率上升。

<!-- OK -->
## 系统: 连击（P-02: 不间断的爽快感）
连续命中时倍率上升。为了 P-02，连击宽限时间要长到不会因1次操作失误而中断。
```

### 数值为初始值＋调整范围

```markdown
<!-- NG -->
玩家速度: 偏快。敌人HP: 以后再定。

<!-- OK -->
| 参数 | 初始值 | 调整范围 | 依据 |
|---|---|---|---|
| 玩家移动速度 | 220 px/s | 180–280 | P-02: 约3秒横穿1个画面 |
| 敌人HP（小怪） | 3 | 2–5 | 3次命中击破的手感 |
```

### 稳定ID

```markdown
<!-- NG: 删除 P-03 并把 P-04 提前为 P-03 -->
- P-01: ...
- P-02: ...
- P-03: （原P-04的内容）

<!-- OK: 以注记表示废止，编号不变 -->
- P-01: ...
- P-02: ...
- P-03: （废止: 因范围过大，于 Checkpoint A 决定删除）
- P-04: ...
```
